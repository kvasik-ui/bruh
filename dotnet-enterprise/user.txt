Руководство пользователя: Docker (контейнеризация приложений .NET)

1. Введение
1.1 Область применения. Упаковка приложений .NET в контейнеры и запуск их вместе с базой данных SQL Server.
1.2 Уровень подготовки пользователя. Умение работать в терминале Ubuntu и выполнять команды с sudo, а также знание предметной области задания.

2. Назначение и условия применения
Упаковка приложений .NET в контейнеры и запуск их вместе с базой данных SQL Server. Условия применения: Ubuntu 26.04 LTS; права sudo; свободное место не менее 10 ГБ; ОЗУ не менее 4 ГБ.

3. Подготовка к работе
3.1 Порядок загрузки программы (команды выполняются по одной):
sudo snap install rider --classic
sudo apt install dotnet-sdk-8.0 -y
dotnet new webapi -n MyApi
dotnet add package Microsoft.EntityFrameworkCore.Design
dotnet tool install --global dotnet-ef
dotnet build
dotnet list package --vulnerable
sudo apt install docker.io -y
sudo systemctl enable --now docker
sudo docker run -d --name mssql -e "ACCEPT_EULA=Y" -e 'MSSQL_SA_PASSWORD=Strong!Pass123' -p 127.0.0.1:1433:1433 mcr.microsoft.com/mssql/server:2022-latest
3.2 Проверка работоспособности. Выполните команды:
dotnet --version
Команды должны завершиться без ошибок и вывести версии или статус установленных компонентов.
3.3 Запуск. Команды Docker выполняются в терминале. Выйдите из системы и войдите снова после добавления в группу docker.

4. Описание операций
4.1 Операция 1. Сборка образа приложения .NET
Условия выполнения: В каталоге проекта есть Dockerfile; Docker запущен.
Подготовительные действия: убедиться, что условия выполнены, и открыть нужный раздел программы.
Основные действия:
1. Выполните docker build -t my-app:1.0 .
2. Дождитесь окончания сборки.
3. Проверьте наличие образа командой docker images.
Результат: образ my-app:1.0 создан.

4.2 Операция 2. Запуск контейнера
Условия выполнения: Образ собран.
Подготовительные действия: убедиться, что условия выполнены, и открыть нужный раздел программы.
Основные действия:
1. Выполните docker run -d -p 8080:8080 --name my-app my-app:1.0.
2. Проверьте статус командой docker ps.
Результат: приложение работает в контейнере.

4.3 Операция 3. Просмотр журналов контейнера
Условия выполнения: Контейнер запущен.
Подготовительные действия: убедиться, что условия выполнены, и открыть нужный раздел программы.
Основные действия:
1. Выполните docker logs my-app.
2. Для потоковой выдачи добавьте флаг -f.
Результат: журнал выведен, ошибки найдены.

4.4 Завершение работы
Условия выполнения: все операции выполнены, результаты сохранены.
Основные действия:
1. Сохранить результаты в программе.
2. Закрыть программу штатным способом: меню «Файл» → «Выход» или сочетание Ctrl+Q.
3. Если на экране появился запрос на подтверждение, подтвердить закрытие программы.
4. Для программ, запущенных в терминале, остановить процесс сочетанием Ctrl+C.
Результат: программа закрыта, данные сохранены.

5. Аварийные ситуации
Нет доступа к демону Docker: проверьте службу sudo systemctl status docker и группу docker. Контейнер завершается сразу: посмотрите журнал docker logs и код выхода docker ps -a.
Восстановление: переустановите программу командами раздела 3.1; данные восстанавливайте из последней резервной копии (например, sudo timeshift --create или архив tar).

6. Рекомендации по освоению
Не храните пароли в Dockerfile: используйте переменные окружения или секреты. Регулярно обновляйте базовые образы. Регулярно обновляйте систему командами sudo apt update && sudo apt upgrade -y.
