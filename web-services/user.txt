Руководство пользователя: Postman (тестирование API)

1. Введение
1.1 Область применения. Отправка HTTP-запросов к программным интерфейсам (REST API), проверка ответов сервера и автоматизация тестов.
1.2 Уровень подготовки пользователя. Умение работать в терминале Ubuntu и выполнять команды с sudo, а также знание предметной области задания.

2. Назначение и условия применения
Отправка HTTP-запросов к программным интерфейсам (REST API), проверка ответов сервера и автоматизация тестов. Условия применения: Ubuntu 22.04 LTS и новее (проверено на 26.04 LTS), 64-разрядная; процессор x86-64 от 1 ГГц; ОЗУ не менее 4 ГБ; диск не менее 1 ГБ; snapd.

3. Подготовка к работе
3.1 Порядок загрузки программы (команды выполняются по одной):
sudo apt install snapd -y
sudo snap install postman
3.2 Проверка работоспособности. Выполните команды:
snap list postman
Команды должны завершиться без ошибок и вывести версии или статус установленных компонентов.
3.3 Запуск. Запустите командой postman или из меню приложений.

4. Описание операций
4.1 Операция 1. Отправка GET-запроса
Условия выполнения: Программа запущена, есть подключение к интернету.
Подготовительные действия: убедиться, что условия выполнены, и открыть нужный раздел программы.
Основные действия:
1. Нажмите New → HTTP Request.
2. Выберите метод GET, введите адрес https://jsonplaceholder.typicode.com/posts/1.
3. Нажмите Send и проверьте код 200 OK и тело ответа JSON.
Результат: ответ получен и сохранён в истории запросов (History).

4.2 Операция 2. Отправка POST-запроса с телом JSON
Условия выполнения: Программа запущена, есть подключение к интернету.
Подготовительные действия: убедиться, что условия выполнены, и открыть нужный раздел программы.
Основные действия:
1. Выберите метод POST, введите адрес https://jsonplaceholder.typicode.com/posts.
2. Во вкладке Body выберите raw и JSON, введите тело запроса.
3. Нажмите Send и проверьте код 201 Created.
Результат: сервер вернул созданный объект.

4.3 Операция 3. Сохранение запроса в коллекцию
Условия выполнения: Запрос отправлен, получен ответ.
Подготовительные действия: убедиться, что условия выполнены, и открыть нужный раздел программы.
Основные действия:
1. Нажмите Save, выберите New Collection, введите имя «API-тесты».
2. Нажмите Save.
Результат: запрос сохранён в коллекцию на боковой панели Collections.

4.4 Операция 4. Написание и запуск теста
Условия выполнения: Запрос сохранён в коллекцию.
Подготовительные действия: убедиться, что условия выполнены, и открыть нужный раздел программы.
Основные действия:
1. Откройте вкладку Tests и введите код проверки статуса 200 (pm.response.to.have.status(200)).
2. Нажмите Send и откройте Test Results.
Результат: результат проверки Passed или Failed.

4.5 Операция 5. Экспорт коллекции в файл
Условия выполнения: Коллекция создана.
Подготовительные действия: убедиться, что условия выполнены, и открыть нужный раздел программы.
Основные действия:
1. Откройте меню коллекции (…) и выберите Export.
2. Выберите Collection v2.1 и сохраните файл .json.
Результат: файл коллекции сохранён для резервной копии.

4.6 Завершение работы
Условия выполнения: все операции выполнены, результаты сохранены.
Основные действия:
1. Сохранить результаты в программе.
2. Закрыть программу штатным способом: меню «Файл» → «Выход» или сочетание Ctrl+Q.
3. Если на экране появился запрос на подтверждение, подтвердить закрытие программы.
4. Для программ, запущенных в терминале, остановить процесс сочетанием Ctrl+C.
Результат: программа закрыта, данные сохранены.

5. Аварийные ситуации
Could not get response: нет сети или файрвол блокирует запрос. Проверьте подключение (ping -c 3 google.com) и правила sudo ufw status. Ошибка SSL-сертификата: для тестовой среды можно отключить проверку в Settings; в боевой среде отключать нельзя. Программа не запускается после установки: выполните sudo snap remove postman и установите заново.
Восстановление: переустановите программу командами раздела 3.1; данные восстанавливайте из последней резервной копии (например, sudo timeshift --create или архив tar).

6. Рекомендации по освоению
Сохраняйте запросы в коллекции по разделам API. Используйте переменные окружения для адресов стендов. Не храните пароли и ключи в открытом виде. Регулярно обновляйте систему командами sudo apt update && sudo apt upgrade -y.
